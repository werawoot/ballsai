# แผนธุรกิจแผนที่ 1 — ขายให้ผู้จัดการแข่งขัน (Organizer-first)

สถานะ: **ร่างสมมติฐาน ยังไม่ผ่านการพิสูจน์** (7 พ.ย. 2026)
ยังไม่มีผู้จัด รายการ หรือผลแข่งจริงในฐานข้อมูล ตัวเลขทุกตัวในเอกสารนี้เป็น **สมมติฐานที่ต้องตรวจใน
Closed Beta** ไม่ใช่ข้อเท็จจริง ห้ามอ้างเป็นยอดขายหรือเรียกว่า "100%" (AGENTS.md ข้อ 11)

## 1. สรุปแผนใน 5 บรรทัด

1. ลูกค้าที่จ่ายเงินก่อนคือ **ผู้จัดการแข่งขัน** (โรงเรียน สโมสร สมาคม ผู้จัดลีกเยาวชน)
2. สิ่งที่ขายคือ **ระบบจัดรายการครบวงจร**: รับสมัครทีม ตรวจสลิป บันทึกผล และออก Player Card / Power Rating /
   Badge ให้นักกีฬาทุกคนอัตโนมัติ
3. นักกีฬา ผู้ปกครอง และโค้ช **ใช้แกนกลางฟรี** (Player Card, Career Passport) เพราะเป็นตัวสร้างความไว้วางใจ
   และข้อมูลผู้เยาว์ไม่ควรอยู่หลัง paywall
4. รายได้หลัก = **ค่าบริการต่อรายการ** + ส่วนเสริมสำหรับรายการใหญ่ รายได้รองในอนาคต = สปอนเซอร์
5. เป้าหมายเฟสนี้ไม่ใช่กำไร แต่คือ **พิสูจน์ว่ามีผู้จัดอย่างน้อย 1–2 รายยอมจ่าย** และรู้ว่าราคาเท่าไร

## 2. ปัญหาของผู้จัด (ที่ระบบแก้ได้ตอนนี้)

อ้างอิงฟีเจอร์ที่มีอยู่ใน README/AGENTS.md: ทัวร์นาเมนต์ ลงทะเบียนทีม อัปโหลดและยืนยันสลิป บันทึกผลแข่ง
พร้อม rating preview ยกเลิกผล (void) XP/Badge trigger และคิวตรวจไฮไลต์

| งานมือของผู้จัดวันนี้ (สมมติ) | สิ่งที่ระบบทำแทน |
|---|---|
| รับสมัครผ่านแชท/ฟอร์มกระจัดกระจาย | ลงทะเบียนทีมผ่านหน้าเว็บเดียว |
| ตามตรวจสลิปโอนเงินจากไลน์ | อัปโหลดสลิปแบบ private ผู้จัดยืนยันในระบบ (signed URL 60 วินาที) |
| จดผลลงกระดาษ/ชีต | บันทึกผลพร้อมตัวเลขที่ตรวจสอบได้ และแก้ไขด้วย void |
| ทำสถิติ/โล่/ใบประกาศหลังจบ | การ์ด Power Rating XP Badge สร้างจากผลที่ยืนยันแล้ว |
| ผู้ปกครองถามหาผลและรูป | Career Timeline และไฮไลต์ของนักกีฬาแต่ละคน |

ข้อสำคัญ: ต้องไม่ยืนยันกับผู้จัดว่า "เขาเจ็บปวดกับข้อใดมากที่สุด" จนกว่าจะสัมภาษณ์จริง (ดู §8)

## 3. ลูกค้าเป้าหมาย (ลำดับตามความง่ายในการปิดการขาย)

1. **ผู้จัดรายการเยาวชนขนาดเล็ก–กลาง** (8–32 ทีม) เจ้าของคนเดียวตัดสินใจเร็ว เหมาะเป็นผู้ทดลอง
2. **โรงเรียน/อะคาเดมี/สโมสร** ที่จัดรายการภายในหรือเชิญ ใช้ร่วมกับโมดูลองค์กร (`docs/organization-flow-v1.md`)
3. **สมาคม/ลีกระดับจังหวัด** รอบถัดไป ต้องการ SLA และการรองรับหลายรายการต่อฤดูกาล

กฎผลิตภัณฑ์ที่ต้องรักษา: ผู้จัดใช้งานได้ **คนเดียวตั้งแต่ต้น** โดยไม่ต้องรอใครเชิญ
ข้อมูลนักกีฬาจะเข้าระบบเมื่อทีมสมัครจริงเท่านั้น

## 4. โครงสร้างรายได้ (ร่าง)

> ตัวเลขราคาเป็น **ค่าตั้งต้นสำหรับทดสอบความเต็มใจจ่าย** ไม่ใช่ราคาที่ตกลงแล้ว

| ระดับ | ใคร | เนื้อหา | ราคาตั้งต้นที่จะทดสอบ |
|---|---|---|---|
| **ทดลอง** | ผู้จัด Beta 1–2 รายแรก | ใช้ครบทุกฟีเจอร์ 1 รายการ แลกกับการสัมภาษณ์และ feedback | ฟรี (แลกข้อมูล) |
| **ต่อรายการ** | ผู้จัดรายการเล็ก–กลาง | รับสมัคร ตรวจสลิป บันทึกผล การ์ดนักกีฬาทุกคนในรายการ | ทดสอบช่วง 1,500–5,000 บาท/รายการ |
| **รายการใหญ่** | 32+ ทีม หรือหลายสนาม | ตั้งค่าให้ ช่วยดูแลวันแข่ง หน้าสปอนเซอร์ ใบประกาศ | ทดสอบช่วง 8,000–20,000 บาท/รายการ |
| **รายปี (ภายหลัง)** | โรงเรียน/สโมสร/สมาคม | หลายรายการ + โมดูลองค์กร | กำหนดหลังได้ข้อมูลจากสองระดับบน |

ทางเลือกที่ **ไม่ทำในเฟสนี้**: หักเปอร์เซ็นต์ค่าสมัครทีม เพราะตอนนี้เงินโอนตรงหาผู้จัดผ่านสลิป การเก็บเงินแทนต้องมี
ระบบชำระเงินและความรับผิดตามกฎหมาย จะประเมินเมื่อมีผู้จัดจ่ายจริงแล้วเท่านั้น

รายได้รองที่เก็บไว้ภายหลัง: ผู้สนับสนุนรายการ (ดู `docs/sponsor-brand-flow-v1.md`) โดยเงื่อนไขเด็ดขาดคือ
**ไม่ขายหรือเปิดข้อมูลส่วนตัวของเยาวชนให้บุคคลที่สาม** สปอนเซอร์ได้พื้นที่แบรนด์เท่านั้น

## 5. สิ่งที่ต้องมีก่อนเก็บเงินจริง

ตาม AGENTS.md รายการเหล่านี้ยังเป็นงานค้าง ต้องปิดก่อนเรียกผู้จัดรายแรกว่า "ใช้งานจริง":

- [ ] apply SQL ขั้น 1–16 ใน `docs/closed-beta-runbook.md` §3 (โดยเฉพาะ `match-result-void-v1` และ
      `guardian-consent-enforcement-v1`) และสร้าง bucket `slips` แบบ private
- [ ] ตั้ง `profiles.role` ของผู้จัด และเพิ่มผู้ทดสอบใน Google OAuth
- [ ] Closed Beta W1 ผ่านครบขั้นตอนด้วยข้อมูลจริง (สคริปต์ใน runbook §6)
- [ ] ความยินยอมผู้ปกครองสำหรับผู้เยาว์ใช้ได้ทั้งฝั่งหน้าเว็บและ trigger ในฐานข้อมูล
- [ ] ช่องทางรับเงินค่าบริการจากผู้จัด (เฟสแรกใช้ใบแจ้งหนี้/โอนตรงนอกระบบได้ ไม่ต้องสร้างระบบจ่ายเงินในแอป)
- [ ] ข้อตกลงการใช้งานผู้จัด (ผู้จัดเป็นผู้ควบคุมข้อมูลรายการ ระบบเป็นผู้ประมวลผล) ให้ที่ปรึกษากฎหมายตรวจ
      ก่อนใช้จริง

## 6. แผนพิสูจน์ใน Closed Beta

| ขั้น | ทำอะไร | ตัวชี้วัดผ่าน |
|---|---|---|
| 1. สัมภาษณ์ | คุยผู้จัดจริง 5 ราย ถามว่าทำรายการล่าสุดอย่างไร ใช้เวลา/เงินกับงานมือเท่าไร | ผู้จัดอย่างน้อย 3 ใน 5 ยืนยันปัญหาเดียวกัน |
| 2. นำร่อง | ผู้จัด 1–2 ราย จัดรายการจริง 1 รายการบนระบบ ฟรี | รายการจบครบ: สมัคร ยืนยันสลิป บันทึกผล ออกการ์ด |
| 3. วัดผล | เวลาที่ผู้จัดประหยัด จำนวนข้อผิดพลาดที่ต้องแก้มือ ความพึงพอใจของผู้ปกครอง | ผู้จัดบอกตัวเลขเวลาที่ประหยัดได้ด้วยตัวเอง |
| 4. ทดสอบราคา | เสนอราคาต่อรายการสำหรับรายการถัดไป | ผู้จัดอย่างน้อย 1 รายตกลงจ่ายจริง |

เกณฑ์ตัดสิน: ถ้าไม่มีผู้จัดรายใดยอมจ่ายหลังนำร่อง 2 รายการ ให้กลับไปทบทวนกลุ่มลูกค้าหรือคุณค่า
ที่เสนอ ก่อนลงทุนสร้างระบบเก็บเงินหรือขยายฟีเจอร์

## 7. ตัวเลขที่ต้องเก็บ (เพื่อให้คุยราคาด้วยหลักฐาน)

- จำนวนผู้จัดที่สัมภาษณ์ / ยอมนำร่อง / ยอมจ่าย
- จำนวนทีมและนักกีฬาต่อรายการ และสัดส่วนที่มีการ์ดจริง (ไม่ใช่ STARTER) หลังรายการจบ
- เวลาที่ผู้จัดใช้ตรวจสลิปและบันทึกผล เทียบวิธีเดิม
- จำนวนครั้งที่ผู้จัดต้องขอให้ทีมงานแก้ข้อมูลด้วยมือ (ตัวชี้วัดงานมือที่โตตามจำนวนผู้ใช้)
- ต้นทุนต่อรายการ: ค่า Supabase/โฮสติ้ง และเวลาของทีมงานที่ช่วยวันแข่ง

## 8. สมมติฐานที่ยังไม่รู้ และความเสี่ยง

| ความเสี่ยง | ผลกระทบ | วิธีลด |
|---|---|---|
| ผู้จัดไม่เห็นว่างานมือเจ็บพอจะจ่าย | ไม่มีรายได้ | สัมภาษณ์ก่อนสร้างเพิ่ม นำร่องฟรีเพื่อวัดเวลาที่ประหยัดได้จริง |
| ค่าสมัครทีมโอนตรงนอกระบบ ผู้จัดไม่อยากเปลี่ยนวิธี | ยืนยันสลิปไม่ถูกใช้ | ให้ระบบเสริมวิธีเดิม ไม่บังคับเปลี่ยน |
| การ์ดเป็นแค่ค่าเริ่มต้น (STARTER) ผู้ปกครองไม่เชื่อถือ | ขายคุณค่า "ผ่านการยืนยัน" ไม่ได้ | แสดงที่มาข้อมูล `self` / `coach_verified` / `performance_verified` ให้ชัด ไม่แสดงค่าเริ่มต้นเป็นผลงาน |
| ข้อมูลผู้เยาว์รั่วหรือใช้ผิดวัตถุประสงค์ | ความเสียหายต่อเด็กและชื่อเสียง | RLS, ความยินยอมผู้ปกครอง, ไม่ขายข้อมูลให้บุคคลที่สาม, ตรวจ PDPA ก่อนเปิดจริง |
| งานมือต่อทีมงานเพิ่มตามจำนวนรายการ (ตั้งค่า ตรวจสอบ) | ขยายระดับประเทศไม่ได้ | บันทึกทุกงานมือใน §7 และวางแผนทำให้เป็นอัตโนมัติ ตามเช็กลิสต์ใน AGENTS.md "Target: nationwide use" |

## 9. การขยายระดับประเทศ (ยังไม่ผ่านเกณฑ์)

ตามกฎ 5 ข้อใน AGENTS.md แผนนี้ **ยังไม่พร้อมสำหรับการใช้งานระดับประเทศ** เหตุผล: ยังไม่มีหลักฐานจากการทดสอบโหลด
การทำซ้ำคำขอ และ RLS ด้วย JWT จริง และรายการเพิ่มทีมงานมือต่อผู้จัดยังไม่ถูกนับ รายละเอียดงานปิดช่องว่างอยู่ใน
[`docs/national-readiness.md`](national-readiness.md) แผนธุรกิจนี้เป็นแผนเฟสพิสูจน์ ไม่ใช่แผนขยาย

## 10. ขั้นถัดไป

1. เจ้าของผลิตภัณฑ์เลือกผู้จัด 5 รายสำหรับสัมภาษณ์ (ใช้เครือข่ายที่มีอยู่)
2. ปิดรายการ §5 ที่เป็นของทีมเทคนิค แล้วรัน Closed Beta W1
3. เลือกผู้จัดนำร่อง 1–2 ราย และเริ่มเก็บตัวเลข §7 ตั้งแต่วันแรก
4. ทบทวนเอกสารนี้หลังนำร่อง ปรับราคาและกลุ่มลูกค้าตามหลักฐาน
