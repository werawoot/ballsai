# UX audit รอบ 7 — ผู้ใช้ใหม่ถึง Player Card

UX: Flow 1 — 7 ต.ค. 2026 — ตรวจโค้ดบน `origin/main` (`15464e5`, มี PR #86; branch `claude/funny-bohr-aoffz9`) และทำ responsive HTML storyboard ใน local workspace

## ขอบเขตและสิ่งที่ยังไม่ยืนยัน

- ตรวจเส้นทางจาก `app/login/LoginPanel.tsx`, `app/welcome/OnboardingFlow.tsx`, `/card`, `/profile`, `/guardian`, `/tournaments`, `SiteNav`, API สมัครทีม และกติกาความพร้อมโปรไฟล์ในโค้ด/เอกสาร
- **ไม่ได้ล็อกอินหรือส่ง OTP/Google จริง**, ไม่ได้ใช้บัญชีผู้ทดสอบ, ไม่ได้เรียก Supabase, ไม่ได้เปิด Production และไม่เปลี่ยนข้อมูลหรือโค้ดแอป
- ทำ mockup responsive ที่ `mockups/v6-flow1.html` แสดง flow หน้าล็อกอิน, Welcome 3 ขั้น, การ์ด STARTER, โปรไฟล์ และทางแยกผู้ปกครอง/โค้ช ไม่มีรูปเด็ก/ข้อมูล Production/สถิตินักกีฬาสมมติ; ทักษะที่ยังไม่ประเมินใช้ `—`
- เบราว์เซอร์ปฏิเสธ `file://` และระบุห้ามเลี่ยงข้อจำกัด จึง **ยังไม่ได้เรนเดอร์/ตรวจภาพด้วยสายตา** ที่ 320, 390 และ 1280 px และไม่มี PNG ประกอบ ไฟล์ HTML มี layout สำหรับมือถือและเดสก์ท็อป แต่ยังยืนยันการไม่ล้นจอไม่ได้
- จำนวนแตะด้านล่างคำนวณจากโค้ดและสมมติฐานที่ระบุ ไม่ใช่ผลทดสอบกับคนจริง; เวลา OTP, การรับเมล, Google consent, 4G และคีย์บอร์ดมือถือยังไม่ถูกวัด

## จำนวนหน้าและแตะ

นับจากหน้าแรก; ไม่นับการพิมพ์อีเมล/OTP เป็นแตะ แต่รวมแตะเพื่อโฟกัสช่องอีเมล; OTP มี `autoFocus`; ฟุตบอลและเป้าหมายแนะนำถูกเลือกไว้แล้วโดยโค้ด

| วิธีเข้าใช้ | ถึง preview แรกที่ `/card` | ถึงการ์ดที่ใส่ชื่อและบันทึก | ถึง `/profile` | หน้าจอผู้ใช้ถึง preview |
| --- | ---: | ---: | ---: | ---: |
| Email OTP | 10 แตะ | 13 แตะ | 14 แตะ | 8 หน้าจอ |
| Google | 7 แตะในแอป + การแตะบนหน้า Google ที่เปลี่ยนตาม session | 10 + ขั้น Google | 11 + ขั้น Google | 6 หน้าจอในแอป + หน้า Google ตาม session |

รายละเอียด Email OTP: หน้าแรก→เข้าสู่ระบบ (1), ติ๊กข้อกำหนด/PDPA (1), เลือกอีเมล (1), โฟกัสช่องอีเมล (1), ส่งรหัส (1), ยืนยันรหัส (1), Welcome เลือกบทบาทและต่อไป (2), ต่อไปเรื่องกีฬา (1), เริ่มตามเป้าหมาย (1) = 10 แตะจน `/card` แสดง preview. เส้นทางมีหน้า Home, login 3 สถานะ, Welcome 3 ขั้น และ Card รวม 8 หน้าจอ; callback เป็น redirect ชั่วคราว ไม่นับเป็นหน้าจอ. ถ้าต้องการการ์ดที่มีชื่อ ต้องแตะแท็บ “ข้อมูล”, แตะช่องชื่อ, และ “บันทึก” อีก 3 แตะ. จาก `/card` ไป `/profile` แตะแถบล่างอีก 1 ครั้ง.

ถ้าเปลี่ยนกีฬา/เป้าหมายจากค่าที่เลือกไว้ จะเพิ่มอย่างน้อย 1 แตะต่อการเลือก. การใส่รูปเป็นทางเลือก ไม่รวมในการนับ. Card preview แสดงทันที แต่เริ่มด้วย `YOUR NAME`; จึงแยก “เห็นการ์ด” ออกจาก “บันทึกการ์ดที่เป็นตัวเอง” ในตัวเลขข้างต้น.

## สิ่งที่พบ เรียงตามผลต่อรอบทดสอบ

1. **[ทุกคน · จุดเข้าระบบ] OTP และ Google ยังไม่ผ่านการทดสอบส่งจริงในขอบเขตนี้** — ถ้ารหัสไม่ถึงหรือผู้ทดสอบเจอ rate limit จะไปไม่ถึง Welcome เลย. โค้ดมีขั้นส่ง/ยืนยัน/รอส่งใหม่ แต่ local storyboard ยืนยันผู้ส่งและ OAuth ไม่ได้. ก่อนนัดกลุ่มควรให้เจ้าของทดสอบกล่องเมลและ Google ด้วยบัญชีทดสอบจริงอย่างละหนึ่งครั้ง; ไม่ใช้บัญชี/OTP แทนเจ้าของ.
2. **[ผู้ปกครองสมัครให้ลูก] ผู้ปกครองสร้างบัญชีนักกีฬาแทนไม่ได้** — บทบาทผู้ปกครองพาไป `/guardian`; หน้านี้เชื่อมได้เมื่อนักกีฬามีบัญชีและโปรไฟล์แล้ว และการเชื่อมยังต้องให้บัญชีนักกีฬาตอบรับ. ถ้าผู้ปกครองเริ่มก่อนลูก จะติด/กลับไปถามใน LINE. ต้องบอกลำดับ “ลูกเริ่มบัญชีก่อน” ตั้งแต่ก่อนเปิด `/guardian`; ข้อความยินยอมเดิมห้ามแก้.
3. **[นักกีฬา 12/16] Preview แสดงก่อนการ์ดมีชื่อ** — หน้า `/card` เริ่มแท็บรูปและแสดง `YOUR NAME`; ช่องชื่ออยู่แท็บข้อมูลและปุ่มบันทึกจะปรากฏเมื่อมีการแก้. มีโอกาสเข้าใจว่า preview คือการ์ดเสร็จ หรือไม่รู้ว่าต้องบันทึก. ไม่มีรูปไม่ขวางการทำต่อ. ไม่มีอันดับให้แสดงเป็น STARTER และทักษะว่างเป็น `—` ตามกฎ. หมายเหตุ: โค้ดใช้ `MF` เป็น fallback เมื่อตำแหน่งยังว่าง จึงควรตรวจว่าผู้ทดสอบไม่อ่านเป็นการประเมินจริง.
4. **[นักกีฬา 12/16 และผู้ปกครอง] การ์ดส่วนตัวไม่เท่ากับโปรไฟล์สาธารณะ** — ทั้งอายุ 12 และ 16 ยังทำการ์ดส่วนตัวได้. อายุไม่ถูกถามใน Welcome หรือ `/card`; ต้องกรอกวันเกิดใน `/profile/edit` ก่อนระบบจะระบุขั้นผู้ปกครอง. โปรไฟล์สาธารณะยังต้องมีวันเกิดและความยินยอมผู้ปกครองตามกติกา (ในโค้ดปัจจุบันเกณฑ์อายุต่ำกว่า 20). เด็กอาจถามว่าทำไมแชร์ภาพได้แต่เปิดลิงก์สาธารณะไม่ได้ หรือไม่รู้ว่าให้ผู้ปกครองทำอะไรต่อ. ห้ามข้าม gate หรือแก้ถ้อยคำกฎหมาย.
5. **[โค้ช/หัวหน้าทีม] หาเส้นทางสมัครทีมเจอแบบมีเงื่อนไข** — เลือก persona “โค้ช / ผู้จัด” แล้วเป้าหมายแนะนำ “หารายการแข่ง” จะพาไป `/tournaments`; แตะการ์ดรายการ → หน้า detail → “สมัครทีม” → ตั้งชื่อทีม. เส้นทางมีจริงในโค้ดและ API อนุญาต persona โค้ช. แต่ถ้าเลือกเป้าหมายอื่นหรือข้าม Welcome จะไม่ถูกพาไปหน้ารายการตรง ๆ. ไม่ได้เปิดข้อมูลรายการ Production จึงไม่ยืนยันว่ารายการที่เจ้าของแจ้งปรากฏใน local mock หรือว่าปุ่มสมัครใช้ได้กับบัญชีจริง.
6. **[ทุกคน · 320 px] การตรวจขนาดยังไม่ครบ** — มี responsive storyboard ที่กำหนด single-column สำหรับมือถือและหลายคอลัมน์บนเดสก์ท็อป แต่ไฟล์ถูก browser policy บล็อกก่อน render จึงยังไม่ยืนยันการตัดบรรทัดไทย, keyboard, touch target หรือ horizontal overflow ที่ 320/390 px.

## คำถามที่คาดว่าจะเข้ากลุ่ม LINE

- “รหัส OTP ยังไม่มา/ขอซ้ำได้เมื่อไร?” — ต้องทดสอบผู้ส่งจริงและข้อความรอให้เจ้าของก่อน; ยังสรุปไม่ได้จาก mock.
- “ลูกยังไม่มีบัญชี ผู้ปกครองสมัครแทนได้ไหม?” — flow ปัจจุบันต้องให้นักกีฬาเริ่มบัญชีก่อน แล้วผู้ปกครองเชื่อมและนักกีฬาตอบรับ.
- “การ์ดขึ้น YOUR NAME แล้วต้องทำอะไร?” — ไปแท็บข้อมูล ใส่ชื่อ และบันทึก; รูปไม่ใช่เงื่อนไข.
- “ทำไมยังเปิดโปรไฟล์สาธารณะ/แชร์ลิงก์ไม่ได้?” — วันเกิดและขั้นความยินยอมผู้ปกครองยังจำเป็น; การ์ดส่วนตัวทำได้ก่อน.
- “โค้ชต้องกดอะไรเพื่อสมัครทีม?” — เลือก “หารายการแข่ง” ใน Welcome, เปิดรายการ แล้วกด “สมัครทีม”; การเลือกโค้ชไม่ให้สิทธิ์สร้างรายการแข่ง.

## สิ่งที่เสนอให้ทำก่อนเริ่มทดสอบ / สิ่งที่รอได้

**ก่อนเริ่มได้ (UI/การเตรียมงานเล็ก ไม่แตะฐานข้อมูล — ทำหลังเจ้าของอนุมัติเท่านั้น):**

- ให้เจ้าของตรวจ OTP และ Google จริงด้วยบัญชีทดสอบก่อนเชิญผู้ทดสอบ; จดผล/เวลารอและช่องทางช่วยเหลือ ไม่ขอ OTP จากผู้ทดสอบในกลุ่ม
- วางคำแนะนำลำดับบัญชีเด็ก→ผู้ปกครองไว้ก่อนหน้า `/guardian` โดยไม่แก้ข้อความ consent/PDPA
- ทำจุด “ใส่ชื่อแล้วบันทึก” บน `/card` ให้เห็นตั้งแต่ preview; คง STARTER และ `—` ไว้ และไม่บังคับใส่รูป
- แยกสถานะ “การ์ดส่วนตัว” กับ “โปรไฟล์สาธารณะ” และทางกลับไป `/profile` ให้เห็น; ไม่เปลี่ยนกฎอายุ/ความยินยอม
- ทดสอบเส้นทางโค้ชบน Preview/local data ที่ไม่ใช่ Production ก่อนนัดจริง; ยืนยันว่ารายการเปิดอยู่แสดงและสร้าง draft team ได้

**รอได้:**

- ปรับธีม/ภาพตกแต่งหรือดีไซน์หน้าแรก (ไม่ทำในงานนี้), แชร์/ดาวน์โหลดหลายรูปแบบ และรายละเอียดสวยงามของการ์ด
- การเปลี่ยนขั้นตอนสมัครทีม/บทบาท หรือการแก้ฐานข้อมูล/สิทธิ์ — ไม่จำเป็นต่อการ audit นี้และต้องแยกอนุมัติ
- การปรับถ้อยคำยินยอม/PDPA/ข้อตกลง — รอนักแปลกฎหมายเท่านั้น
