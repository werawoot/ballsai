## เปลี่ยนอะไร

- ฟอร์มเดิม (dropdown ทีม/นักกีฬา + ช่องพิมพ์สกอร์ + ป้ายอังกฤษ) เป็นขั้นตอนแตะ: เลือกสองทีม → แตะผู้เล่นที่ลงเล่น/ประตู/MVP → ดูตัวอย่าง → ยืนยัน
- สกอร์คำนวณจากประตูที่แตะ จึงไม่ขัดกับผู้ทำประตู ประตูที่ไม่รู้ผู้ทำมีตัวนับแยก
- ถ้ารายการมีทีมที่ยืนยันแล้วสองทีมพอดี ระบบเลือกให้ ไม่ต้องแตะ
- ปุ่มหลักปุ่มเดียวติดล่างจอ บอกเหตุผลเมื่อกดไม่ได้ ไทย/อังกฤษผ่าน `messages/*.json` (`matchEntry`)
- หัวหน้าหน้าเปลี่ยนจากแถบแดงตัวอักษรเส้นขอบเป็นหัวข้อทึบ ตัวเลือกรายการแข่งพับเป็นบรรทัดเดียวเมื่อเลือกแล้ว
- หลังยืนยัน มีปุ่ม "บันทึกนัดต่อไป" และรีเฟรชรายการผลที่บันทึกแล้ว (เดิมต้องโหลดหน้าใหม่)
- **ไม่เปลี่ยน**: API, การคำนวณ Rating, requestId กันบันทึกซ้ำ (sql/60), สิทธิ์, SQL ทุกไฟล์

ไฟล์: `lib/match-entry.ts` (ตรรกะล้วน) · `app/dashboard/results/MatchResultForm.tsx` · `results.css` · `page.tsx` · `messages/{th,en}.json` · `tests/match-entry.test.ts` · เอา 2 ไฟล์ออกจาก `tests/i18n-thai-baseline.json` ตามกฎของ repo เพราะไม่มีข้อความไทยฝังในโค้ดแล้ว

## ที่ยังไม่ได้พิสูจน์ (ตรงไปตรงมา)

- การเรียก `/api/match-results` ในการทดสอบเบราว์เซอร์เป็นคำตอบจำลอง ยังไม่ได้ลองกับ API และ Supabase จริง (Staging เข้าไม่ได้ในตอนนี้) ต้องให้ QA/lead ลองบันทึกผลจริง 1 นัดบน Staging ก่อนใช้
- คำถามเรื่องสกอร์กับผลรายคน: ในส่วนของ `app/api/match-results/route.ts` ที่ผมอ่าน ไม่พบการตรวจว่าสกอร์ทีมเท่ากับผลรวมประตูรายคน แต่ยังไม่ได้อ่านครบทั้งไฟล์และฟังก์ชัน SQL `record_match_result` ต้องให้ lead ยืนยัน (ถ้ามีการตรวจ ฟอร์มนี้ไม่ทำให้เกิดความขัดแย้ง เพราะสกอร์มาจากประตูที่แตะ ยกเว้นประตูไม่ระบุผู้ทำ)
- API ยังกำหนดให้ต้องมีผู้เล่นอย่างน้อย 1 คน ฟอร์มจึงบอกว่า "แตะชื่อผู้เล่นที่ลงเล่นอย่างน้อย 1 คน" แทนที่จะให้บันทึกแค่สกอร์
- ขั้น "เลือกนัดจากตารางแข่ง" ยังไม่ได้ทำ (ไม่อยู่ใน mockup ที่อนุมัติ) ตอนนี้เลือกสองทีมด้วยการแตะ 2 ครั้งเมื่อมีทีมมากกว่า 2
- ยังไม่ได้ทดสอบ: ข้อความไทยยาวมาก, ทีมที่มีผู้เล่น 1,000 คน (ช่องค้นหาโผล่เมื่อเกิน 12 คน แต่หน้านี้ยังโหลดรายชื่อทุกทีมของรายการในครั้งเดียวเหมือนเดิม), offline, 320 px, มือถือจริงกลางแดด, screen reader
- รายการ "ผลที่บันทึกไปแล้ว" (`MatchResultHistory`) และ `TournamentPicker` ไม่ได้ปรับหน้าตา
- ทดสอบ `tests/i18n.test.ts` ข้อ "all format with the real runtime" เคย timeout 1 ครั้งตอนรันขนานกัน (5.1 วินาที เทียบเพดาน 5 วินาที) รันซ้ำผ่านทุกครั้ง ข้อความที่เพิ่มทำให้ช้าลงเล็กน้อย

## nationwide use — 5 ข้อ

1. ข้อมูล 100×: ไม่เปลี่ยนคิวรีหรือดัชนี ฟอร์มวาดรายชื่อผู้เล่นของสองทีมที่เลือกเท่านั้น แต่หน้ายังโหลดรายชื่อทุกทีมที่ยืนยันแล้วของรายการ (พฤติกรรมเดิม) · ยังไม่ได้วัดที่ 100×
2. พร้อมกัน: requestId เดิม ปุ่มยืนยันปิดระหว่างส่ง กดซ้ำ/ส่งซ้ำได้ผลเดียวตามที่ sql/60 รับประกัน · พิสูจน์ในเบราว์เซอร์กับ API จำลองเท่านั้น
3. ข้อมูลเยาวชน: ไม่เปลี่ยนข้อมูลที่ส่งหรือเก็บ
4. งานมือ: ลดจาก ≈ 20 แตะเหลือ 7 ต่อนัด ไม่เพิ่มงานมือ
5. หลักฐาน: ตามหัวข้อด้านบน ข้อ 1 และ 2 ยังไม่ผ่านเกณฑ์ "หลักฐานจริง" จึง**ยังไม่ถือว่าพร้อมใช้ทั่วประเทศ** จนกว่าจะลองบน Staging และวัดที่ปริมาณสูง
