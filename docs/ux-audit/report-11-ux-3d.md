## สรุปสั้น (อ่านแค่ส่วนนี้ก็พอ)

1. **ไม่มีแหล่งไหนที่นำโค้ดมาใช้ตรง ๆ ได้อย่างปลอดภัย** [ยืนยันแล้ว]
   - footbookr ไม่มี License จึงห้ามใช้โค้ด
   - FieldPlay บอกว่า MIT แต่ไม่มีไฟล์ License
   - Kit Customizer มีโมเดลที่ห้ามใช้เชิงพาณิชย์
   - Spline runtime ไม่ระบุ License
   - ThreeUI เป็น MIT แต่แพ็กเกจหนัก 54.7 MB และพก three.js มาอีก 2 ชุด
   - ที่นำมาได้คือ**แนวคิด** ไม่ใช่โค้ด
2. **เว็บเรามีฐานที่ดีอยู่แล้ว** [ยืนยันแล้ว]
   - มีระบบสี `ui.css` และคู่มือ `docs/design-system.md`
   - รองรับคนที่ปิดภาพเคลื่อนไหว 15 จุด
   - ปุ่มใหญ่ 44px และมีเส้นขอบตอนกดคีย์บอร์ด
   - ใช้ `next/image` ทุกที่
   - ภาพท่าฝึก "3D" เป็นภาพนิ่งที่เรนเดอร์ไว้ก่อน ทำให้แอปไม่ต้องโหลด three.js เลย ซึ่งถูกทางสำหรับมือถือราคาถูก
3. **สิ่งที่ควรแก้ก่อนใส่ 3D** [ยืนยันแล้ว]
   - หน้าแรกใช้สีแดง `#d71920` ไม่ตรงกับ `#CC0001` ของทั้งเว็บ
   - ภาพสไลด์หน้าแรกเลื่อนเองทุก 7.5 วินาที ไม่มีปุ่มหยุด และไม่หยุดให้คนที่ปิดภาพเคลื่อนไหว
   - มี inline style 885 บรรทัด
   - Tailwind ติดตั้งไว้แต่แทบไม่ได้ใช้
4. **ข้อเสนอเรื่อง 3D** [ข้อเสนอ]
   - ใช้ 3D แบบ "เรนเดอร์ไว้ก่อนเป็นภาพ" ซึ่งเป็นวิธีเดียวกับภาพท่าฝึก ให้มากที่สุด
   - ใช้ 3D แบบหมุนได้ในเบราว์เซอร์ **ได้ที่เดียว** คือการ์ดนักกีฬาตอนกดดูหรือแชร์ และต้องเป็นตัวเลือกที่ผู้ใช้กดเปิดเอง
   - **ไม่ใช้ Spline** และ**ไม่ใส่ 3D ในหน้าที่ต้องทำงาน** (ล็อกอิน สมัคร บันทึกผล จองสนาม)

## G. แผนงาน (Roadmap) [ข้อเสนอ]

**Phase 1: แก้เร็ว (1–2 วัน)**
1. สไลด์หน้าแรกหยุดได้ และหยุดเองเมื่อผู้ใช้ปิดภาพเคลื่อนไหว
2. แดงหน้าแรกเป็น `#CC0001` (ต้องรอเจ้าของอนุมัติ)
3. เตือนโค้ชให้ตั้งชื่อก่อนเชิญนักกีฬา
4. เปลี่ยนชื่อการ์ด "ส่งสมัครทีม" ให้ไม่สับสนกับการสร้างทีม

**Phase 2: ปรับ UX/UI (1–2 สัปดาห์)**
1. ตั้ง token ระยะห่างและลูกเล่น แล้วย้าย inline style ของหน้าที่ใช้บ่อยมาใช้ token (ครั้งละหน้า พร้อมเทส)
2. แอนิเมชันโหลดรูปลูกฟุตบอล และหน้าว่างที่บอกว่าทำอะไรได้ตอนนี้
3. ตรวจว่า Tailwind ยังจำเป็นไหม แล้วค่อยตัดสินใจถอด [ต้องพิสูจน์ด้วยการ build เทียบขนาด]

**Phase 3: 3D แบบประหยัด (1–2 สัปดาห์)**
1. การ์ดนักกีฬาเอียง 3D ด้วย CSS และแสงวาบตอนได้เหรียญ
2. ภาพสนามและแผนการเล่นแบบเรนเดอร์ไว้ก่อน จาก `scripts/training-art`
3. (ทางเลือก) ต้นแบบการ์ด 3D หมุนได้ที่ผู้ใช้กดเปิดเอง โดยวัดขนาดไฟล์และความเร็วบนมือถือรุ่นเก่าก่อน ถ้าเกินเกณฑ์ให้ตัดทิ้ง

**Phase 4: ทดสอบและปรับ**
- วัด Core Web Vitals จริงจาก `@vercel/speed-insights` ซึ่งติดตั้งอยู่แล้ว
- ตรวจการเข้าถึงด้วยเครื่องมือ (เช่น axe ซึ่งยังไม่ได้ติดตั้ง) และเทสกับผู้ทดสอบ W1 บนมือถือจริง

## H. วิธีวัดผล (ไม่มีตัวเลขเป้าหมายที่เดาขึ้นเอง)

ตอนนี้ยังไม่มีผู้ใช้จริง จึงยังไม่มีตัวเลขฐาน ให้เก็บตัวเลขจากผู้ทดสอบ W1 ก่อน แล้วค่อยตั้งเป้า

| ตัววัด | วัดอย่างไร |
|---|---|
| สมัครแล้วใช้งานได้ภายในกี่นาที (แยกตามบทบาท) | เวลาตั้งแต่ล็อกอินครั้งแรกจนทำงานแรกสำเร็จ เช่น นักกีฬาเห็นการ์ด โค้ชสร้างทีม |
| ผลแข่งถูกบันทึกจนการ์ดอัปเดตครบไหม | สัดส่วนผลแข่งที่ยืนยันแล้วซึ่งเปลี่ยนการ์ดหรือคะแนนได้ |
| จองสนามสำเร็จกี่ % และใช้กี่ขั้น | นับจากคำขอจองถึงการยืนยัน |
| Core Web Vitals บนมือถือ | `@vercel/speed-insights` (LCP, INP, CLS) แยกหน้าแรก โปรไฟล์ และการ์ด |
| การเข้าถึง | ผลตรวจอัตโนมัติ + ทดสอบด้วยคีย์บอร์ดและการปิดภาพเคลื่อนไหว |
| ความรู้สึกผู้ใช้ | ถามผู้ทดสอบ W1 แบบสั้น ๆ ว่า "อยากแชร์การ์ดไหม" และ "ตรงไหนงง" |
