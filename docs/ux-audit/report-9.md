# รายงาน 9 — หน้าหลักตามบทบาท (audit + mockup)

> **local mock ทั้งหมด** ตัวเลขและชื่อใน mockup เป็นตัวอย่าง ไม่ใช่ข้อมูลจริง ยังไม่ได้แก้โค้ดแอป ไม่แตะหน้าแรก ถ้อยคำกฎหมาย SQL หรือ API รอเจ้าของอนุมัติ

## 1. สรุป 6 บรรทัด

1. หน้าที่ทุกบทบาทเจอซ้ำคือ `/profile` ซึ่งเป็นหน้านักกีฬา (ชื่อ, ระดับ, การ์ด, ขั้นของโปรไฟล์) บทบาทอื่นได้แค่ "ทางลัด" เล็ก ๆ ที่ท้ายหน้า
2. "โค้ช" กับ "ผู้จัดแข่ง" ถูกรวมเป็นตัวเลือกเดียว (`coach_organizer`) แต่สิทธิ์จริงแยกกัน: โค้ชสร้างทีมได้จากตัวเลือกนี้ ส่วนแดชบอร์ดผู้จัดต้องให้แอดมินตั้ง `profiles.role` เอง ผลคือโค้ชกดทางลัด "แดชบอร์ดผู้จัดและโค้ช" แล้วเจอหน้า "ยังไม่เปิดสิทธิ์ผู้จัด"
3. คนหนึ่งคนมีบทบาทได้บทบาทเดียวใน `/welcome` และเข้าซ้ำไม่ได้ (หน้าเด้งออกเมื่อเคยทำเสร็จ) โค้ชที่เป็นผู้ปกครองด้วยจึงทำไม่ได้ในบัญชีเดียว
4. เสนอ: ใช้ `/profile` เป็น "หน้าหลักของฉัน" ตามบทบาท โครงเดียวกันทุกบทบาท = ฉันคือใคร → **ปุ่มหลักเดียว** → ทางลัดไม่เกิน 3
5. แถบเมนูล่าง **ไม่เปลี่ยนตามบทบาท** เปลี่ยนแค่ชื่อแท็บที่ 5 จาก "โปรไฟล์" เป็น "ของฉัน"
6. มี 6 เรื่องรอเจ้าของตัดสิน (ข้อ 7) สองเรื่องต้องเปลี่ยนฐานข้อมูล จึงยังไม่ได้ทำอะไร

## 2. แต่ละบทบาทใช้หน้าไหน สิทธิ์อะไร (ตรวจจากโค้ด)

มี 2 ค่าที่ไม่ใช่สิ่งเดียวกัน: `profiles.role` (user / organizer / admin ตั้งโดยแอดมินด้วยมือ) กับ `profiles.onboarding_persona` (ผู้ใช้เลือกเองใน `/welcome` 5 ค่า)

| บทบาท | หน้าที่ใช้ | ใครตัดสินสิทธิ์ | หลักฐานในโค้ด |
|---|---|---|---|

| ผู้ปกครอง | `/guardian` | **persona = guardian** (ขอเชื่อมลูกไม่ได้ถ้าไม่ใช่) | `sql/21-guardian-links-v1.sql:104`, `app/guardian/page.tsx:50` |
| โค้ช | `/team-members`, `/match-plan`, สมัครทีมที่ `/tournaments/[id]` | **persona = coach_organizer หรือ role = organizer/admin** | `sql/20-tournament-roster-flow-v1.sql:59-63`, `app/match-plan/page.tsx:21` |

ทางลัดใน `/profile` สร้างจากสองค่าปนกัน (`app/profile/page.tsx:125-131`): `role` organizer/admin **หรือ** persona coach_organizer → "แดชบอร์ด"; persona venue_owner → "จัดการสนาม"; persona guardian → "ผู้ปกครอง" ส่วน "สมาชิกทีม" ของโค้ชอยู่ในเมนูทั่วไปที่ทุกคนเห็น

หลังเข้าสู่ระบบ: `/auth/callback` → `/welcome?next=…` → ถ้าเคยทำเสร็จแล้วเด้งไป `next` (ปกติคือ `/` หน้าแรกสาธารณะ) มีแต่ครั้งแรกที่ไปตามเป้าหมายที่เลือก (`destinationOf`) ดังนั้น "กลับเข้ามา" ไม่เคยลงหน้างานของตัวเอง

## 4. แบบที่เสนอ

โครงหน้า (ทุกบทบาท): แถบชื่อ + "ในฐานะ …" → **การ์ดงานตอนนี้ มีปุ่มแดงเดียว** → ทางลัดไม่เกิน 3 แถว ส่วนที่เป็นของนักกีฬาเดิม (ระดับ, ขั้นโปรไฟล์, ลบข้อมูล, ออกจากระบบ) ย้ายลงท้ายหน้าหรือไปหน้า "การ์ดของฉัน" ไม่หาย

| บทบาท | ชื่อหน้า | ปุ่มหลัก (เลือกตามงานที่ค้าง ตามลำดับ) | mockup |
|---|---|---|---|
| นักกีฬา | การ์ดของฉัน + ซ้อมวันนี้ | มีซ้อมวันนี้ → "เริ่มซ้อม" · ไม่มี → ขั้นถัดไปของโปรไฟล์ | `v9-1-athlete` |
| ผู้ปกครอง | ลูกของฉัน | ยังไม่มีลูก → "เชื่อมบัญชีลูก" · มี → "ดูความก้าวหน้าของน้อง" | `v9-2-guardian` |
| โค้ช | ทีมของฉัน | ไม่มีทีม → "สมัครทีมเข้ารายการ" · ยังไม่มีคนตอบรับ → "เชิญนักกีฬา" · มีตอบรับ → "ส่งสมัครทีม" | `v9-3-coach` |
| ผู้จัด | รายการของฉัน | มีทีมรอตรวจ → "ตรวจทีมที่รอ (n)" · มีแมตช์รอผล → "บันทึกผลแข่ง" · ไม่มี → "สร้างรายการแข่ง" | `v9-4-organizer` |
| ผู้จัด ไม่มีสิทธิ์ | รายการของฉัน | ไม่มีปุ่มแดง (ไม่มีอะไรให้กดได้จริง) บอก "เกิดอะไรขึ้น" และ "ต้องทำอะไร" **ช่องทางขอสิทธิ์เว้นว่าง ไม่ใส่ปุ่มติดต่อ** ระหว่างนี้ลิงก์ไปงานที่ทำได้ | `v9-4b-organizer-none` |
| เจ้าของสนาม | สนามของฉัน | มีคำขอรอ → "ตอบคำขอจอง (n)" · ไม่มี → "เปิดเวลาว่างเพิ่ม" · ไม่มีสนาม → "เพิ่มสนาม" | `v9-5-venue` |

ตัวเลขในการ์ดมาจากข้อมูลที่มีจริงเท่านั้น (จำนวนทีมรอตรวจ, คำขอจอง, ผู้ตอบรับ) ค่าที่ยังไม่ประเมินแสดง "—" ตามกฎข้อ 8

## 5. คำตอบ 3 ข้อที่ถาม

**แยก "โค้ช" กับ "ผู้จัดแข่ง" ใน /welcome** (`v9-7-welcome`) แยกเป็น 2 แถว แถวผู้จัดบอกตรง ๆ ว่า "ต้องขอสิทธิ์จากผู้ดูแลระบบ" ทางเลือก:
- **ก. ไม่แตะฐานข้อมูล** ทั้งสองแถวเก็บค่าเดิม `coach_organizer` ข้อดีคือทำได้ทันที ข้อเสียคือระบบแยกไม่ออกว่าคนนี้อยากเป็นผู้จัด จึงให้หน้า "ทีมของฉัน" มีแถว "รายการของฉัน (ผู้จัดแข่ง)" ที่พาไปหน้าอธิบายสิทธิ์ (`v9-3`, `v9-4b`)
- **ข. เพิ่มค่าใหม่** `organizer` ใน `profiles_onboarding_persona_check` ต้องมีไฟล์ SQL ใหม่ (ห้ามแก้ไฟล์เก่า) และต้องไล่แก้ทุกที่ที่เช็ก `coach_organizer` ซึ่งตอนนี้คือ `sql/20`, `app/match-plan`, `app/profile` — **ต้องเจ้าของอนุมัติ** แนะนำ ก. ก่อน

**คนหลายบทบาท (เช่น โค้ชที่เป็นผู้ปกครอง)** (`v9-6-multirole`) หน้าหลักแสดงส่วนตาม "สิ่งที่บัญชีมีอยู่จริง" ไม่ใช่ตามที่เลือกครั้งเดียว: มีทีมที่สร้าง → "ทีมของฉัน", มีลิงก์ผู้ปกครอง → "ลูกของฉัน", มีสนาม → "สนามของฉัน", มีรายการ → "รายการของฉัน" ถ้ามีมากกว่าหนึ่ง ใส่แถบสลับ 2-3 ปุ่มใต้ชื่อ (ใหญ่ ≥44 px) จำอันล่าสุดที่เปิด ตัวเลขแดงบอกว่ามีงานรอ
- **ข้อจำกัดที่ต้องรู้:** แสดงผลแบบนี้ทำได้โดยไม่แตะ DB แต่ "เริ่ม" บทบาทที่สองยังไม่ได้ เพราะ RPC ขอเชื่อมลูกเช็ก persona = guardian และ RPC สร้างทีมเช็ก coach_organizer การให้โค้ชขอเชื่อมลูกได้ต้องแก้ฟังก์ชัน SQL ที่เกี่ยวกับผู้เยาว์ จึง **ไม่ทำเองและต้องให้หัวหน้า/เจ้าของตัดสิน**

**แถบเมนูล่างเปลี่ยนตามบทบาทไหม** ไม่เปลี่ยน ทั้ง 5 แท็บเหมือนเดิม (หน้าแรก, ค้นหา, รายการแข่ง, แจ้งเตือน, ของฉัน) เหตุผล: คนหลายบทบาทไม่ต้องเจอแอปที่หน้าตาเปลี่ยน, ทดสอบง่าย, ไม่แตะหน้าแรก, ผู้ใช้ไม่ต้องจำเมนูของอีกบทบาท ที่เปลี่ยนคือเนื้อหาในแท็บ "ของฉัน" เท่านั้น (ต้องแก้ `nav.items.profile` ใน messages)

## 6. ตอบเกณฑ์ "ทั่วประเทศ" (ยังไม่มีตัวเลข เพราะเป็น mockup)

1. ข้อมูล 100×: หน้าหลักใช้ count กับรายการสั้น ไม่เกิน 3-5 แถว แล้วลิงก์ไปหน้ารายการที่แบ่งหน้าอยู่แล้ว ต้องวัดแผน query ตอนลงมือ
2. พร้อมกัน: หน้าหลักอ่านอย่างเดียว ปุ่มหลักพาไปหน้าเดิมที่ idempotent อยู่แล้ว
3. ผู้เยาว์: ผู้ปกครองเห็นเฉพาะลูกที่เชื่อมและยอมรับแล้วผ่าน RLS เดิม ไม่เพิ่มช่องทางอ่าน
4. งานมือ: การตั้ง role ผู้จัดโดยแอดมินโตตามจำนวนผู้จัด (F5) ต้องมีทางขอสิทธิ์เองและคิวให้แอดมินอนุมัติ ซึ่งต้องมี SQL ใหม่ จึงเสนอเป็นงานแยก
5. หลักฐาน: จะแนบผลเทสต์และการวัดเมื่อเริ่มทำจริง รายงานนี้ **ยังไม่ใช่ "พร้อมใช้ทั่วประเทศ"**
