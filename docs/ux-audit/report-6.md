- ข้อมูลทั้งหมดเป็นข้อมูลสมมติ (นักกีฬา "น้องกลับมา ฟุตบอล" ลงทะเบียนโปรแกรม U10 Foundation วันอังคาร/พฤหัส/เสาร์) ไม่มีรูปเด็กจริง ตัวเลขบนการ์ดและอันดับมาจาก mock ไม่ใช่ข้อมูลจริง
- ค่าตัวเลขใน mock ไม่สม่ำเสมอ (เช่น "อันดับของฉัน #3 อยู่ในหน้านี้" กับชื่ออื่นในตาราง) ผมไม่ถือเป็นข้อสังเกตของแอป
- **ไม่ได้ตรวจ**: หน้าจอสรุปหลังซ้อมเสร็จ (สถานะ `done`), การกดบันทึกการซ้อมจริง, `/players/[id]`, หน้า drill รายท่า, เสียง/ตัวจับเวลา, ผลบนมือถือจริงกลางแดด
- จำนวนแตะนับจากหน้าจอและโค้ด ไม่ได้จับเวลากับคนจริง

## ปัญหา (เรียงจากกระทบคนมากที่สุด)

1. **[นักกีฬาที่กลับมา]** เปิด `/profile` ไม่เห็น "วันนี้ทำอะไร" ก่อนเห็นรายการเตรียมโปรไฟล์
   - ทำไมเป็นปัญหา: ลำดับในหน้าคือ หัวโปรไฟล์ → การ์ดรายการเตรียม ("ก่อนเปิดโปรไฟล์สาธารณะ 4 จาก 6" พร้อมปุ่มแดง "ทำขั้นนี้") → การ์ดฝึกซ้อมวันนี้ (ปุ่มแดงอีกปุ่ม "เริ่มซ้อมวันนี้" ต้องเลื่อนลงไปราวครึ่งจอที่ 390 px) จึงมีปุ่มหลักสองปุ่มแข่งกัน และผู้ใช้ที่เปิดสาธารณะแล้ว (ป้าย "สาธารณะ" และปุ่ม "ดูหน้าสาธารณะ" อยู่ด้านบน) ยังเห็นหัวข้อ "ก่อนเปิดโปรไฟล์สาธารณะ" (`f5-a-profile-m.png`) เหตุผลกลับมาใช้ซ้ำที่ระบบมีอยู่จริงคือการซ้อมวันนี้ และอยู่ถัดลงไป
   - ข้อเสนอ: เมื่อมีโปรแกรมซ้อม "วันนี้" เป็นการ์ดแรกใต้หัวโปรไฟล์ รายการเตรียมโปรไฟล์ย่อเป็นบรรทัดเดียว ("ครบ 4 จาก 6 · ถัดไป: รูปนักกีฬา") ไม่ใช่ปุ่มแดง (mockup A) ใช้ข้อมูลที่มีอยู่ ไม่ต้องแก้ฐานข้อมูล
   - วัดผลด้วย: จำนวนการซ้อมที่เริ่มต่อสัปดาห์ต่อนักกีฬาที่ลงทะเบียน · สัดส่วนที่เริ่มซ้อมจาก `/profile` โดยตรง (ตอนนี้ ≈ เลื่อน + 1 แตะ จาก `/profile`)
2. **[นักกีฬาที่กลับมา]** ดูอันดับของตัวเองจาก `/profile` หรือการ์ดไม่ได้
   - ทำไมเป็นปัญหา: บล็อก "การ์ดนักกีฬา" บน `/profile` มี Power Rating กับปุ่ม "สร้างและแชร์การ์ด" ไม่มีอันดับหรือลิงก์ไปอันดับ (ทางลัดมีแค่ จองสนาม, โอกาสสนับสนุน, สมาชิกทีม, Career Passport) ต้องไปที่แถบล่าง "ค้นหา" แล้วเลือกแท็บ Ranking จึงเห็น "อันดับของฉัน" ผลแข่งที่ยืนยันแล้วคือสิ่งที่ระบบสัญญาไว้ว่าจะ "กลายเป็นอันดับ" แต่ผู้ใช้ไม่เห็นผลนั้นตรงจุดที่ตัวเองอยู่
   - ข้อเสนอ: แถวเดียว "อันดับในประเทศ #N · ดูอันดับ ›" บน `/profile` (mockup A) ค่า N ต้องมาจาก `findMyPosition` ของหน้า `/ranking` ซึ่งนับแถวที่คะแนนสูงกว่า **ขอให้หัวหน้าตรวจดัชนีและต้นทุนที่ปริมาณหลายแสนแถวก่อน** (กฎข้อ 1) ถ้าไม่มี rank แสดง "—" ตามกฎข้อ 8 ผมไม่ได้ใส่ตัวเลขจริงใน mockup
   - วัดผลด้วย: การเปิด `/ranking` จาก `/profile` · จำนวนครั้งที่เปิด `/ranking` ต่อนักกีฬาต่อสัปดาห์
3. **[นักกีฬา · ความปลอดภัย]** คำถาม "มีอาการเจ็บไหม?" ให้น้ำหนักภาพไม่เท่ากัน
   - ทำไมเป็นปัญหา: ในโค้ด "ไม่เจ็บ เริ่มซ้อม" เป็นปุ่มหลักสีแดง ส่วน "เจ็บ" เป็นปุ่มรอง (`SessionRunner.tsx`: `ui-btn-primary` กับ `ui-btn-ghost`) และเมื่อเปิดหน้ามีเส้นโฟกัสอยู่ที่ปุ่ม "ไม่เจ็บ" (`f5-e-session-m.png`) เด็กที่อยากเริ่มซ้อมเร็วอาจกดผ่านคำถามความปลอดภัย (ยังไม่ได้ทดสอบกับผู้ใช้จริง นี่เป็นข้อสังเกตด้านการออกแบบ)
   - ข้อเสนอ: ปุ่มสองปุ่มน้ำหนักเท่ากันและป้ายบอกผลชัด ("ไม่เจ็บ · เริ่มซ้อม" / "เจ็บ · ไม่ซ้อมวันนี้") ไม่ปรับถ้อยคำหลักของคำถาม (mockup B) **ขอให้หัวหน้า/ผู้ตรวจโปรแกรมซ้อมยืนยันถ้อยคำก่อน** เพราะเป็นข้อความด้านสุขภาพ
   - วัดผลด้วย: สัดส่วนที่เลือก "เจ็บ" (ไม่มีข้อมูลนี้ตอนนี้และไม่ควรเก็บคำตอบรายบุคคลตามหลักของโปรแกรม ควรดูเฉพาะการใช้งานรวม ถ้าหัวหน้าเห็นว่าทำได้)
4. **[นักกีฬา]** ชื่อบนการ์ดที่แชร์ถูกตัดด้วย "…"
   - ทำไมเป็นปัญหา: ชื่อ "น้องกลับมา ฟุตบอล" แสดงเป็น "น้องกลับมา ฟต…" บนการ์ด (`f5-g-card-m.png`) การ์ดคือสิ่งที่นักกีฬาโพสต์ให้เพื่อนและผู้ปกครองเห็น ชื่อไทยยาวหรือชื่อ-นามสกุลจึงมักยาวเกินบรรทัดเดียว
   - ข้อเสนอ: ชื่อขึ้นสองบรรทัด ลดขนาดเมื่อยาวมาก (mockup C)
   - วัดผลด้วย: จำนวนการแชร์การ์ดต่อนักกีฬา (ถ้ามี event)
5. **[นักกีฬา]** ตัวเลข "Power" บนการ์ดกับบน `/profile` อาจมาจากคนละที่
   - จากโค้ด: การ์ด (`app/card/page.tsx`) แสดง `player_ratings.power_rating` ส่วน `/profile` และ `/ranking` ใช้ `player_ranks.pts` ในชื่อเดียวกันว่า Power Rating ถ้าสองค่านี้ไม่เท่ากันในข้อมูลจริง นักกีฬาจะเห็น "Power" สองค่าในบัญชีเดียว (ใน mock ผมตั้งสองค่าต่างกัน จึงเห็นเลขต่างกัน ซึ่งไม่ใช่หลักฐานว่าจริง) **ขอให้หัวหน้ายืนยันว่าสองค่านี้เท่ากันโดยโครงสร้าง (SQL) หรือไม่**
6. **[นักกีฬา · ข้อสังเกตเรื่องตัวนับ]** การ์ดฝึกซ้อมแสดง "ต่อเนื่อง 0 สัปดาห์" ให้ผู้ที่เพิ่งเริ่ม
   - ตามกฎ "ไม่มี streak guilt" ตัวนับ 0 ที่แสดงเป็นข้อความเชิงลบเล็กน้อย ข้อเสนอ: แสดงเฉพาะเมื่อ ≥ 1 สัปดาห์ (mockup A ไม่แสดง) เป็นเรื่องเล็ก ไม่ต้องแก้ฐานข้อมูล
