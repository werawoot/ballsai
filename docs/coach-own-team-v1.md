# โค้ชสร้างทีมเองได้ ไม่ต้องสมัครรายการ (แบบร่าง v1, 13 ต.ค. 2026)

> **สถานะ: เจ้าของตกลงแล้ว 13 ต.ค. 2026 ("ตามที่แนะนำทั้ง 4 ข้อ")** SQL78 เขียนและทดสอบในเครื่องจำลองแล้ว (runbook แถว 78) ยังไม่ได้ลง Staging/Production
> `AGENTS.md` กำหนดว่างานที่แตะรายชื่อทีม การสมัคร ผลแข่ง และ RLS พร้อมกัน ต้องตกลงแบบก่อน
> ที่มา: กฎ "ทุกบทบาทใช้ของตัวเองได้ก่อน" (`AGENTS.md`, 12 ต.ค. 2026) และแบบร่าง `docs/ux-audit/img/v10-2-coach-team.png`

## 1. ปัญหาตอนนี้ (ตรวจจากโค้ด)

- ทีมหนึ่งทีม = **การสมัครรายการแข่งหนึ่งครั้ง** (`teams.tournament_id`)
  - สร้างทีมได้ทางเดียวคือ `create_tournament_team_safely(tournament, name)` (sql/20) และต้องมีรายการที่เปิดรับสมัครอยู่
- เครื่องมือโค้ชทุกตัวผูกกับ `teams.id` ได้แก่ นัดซ้อม (70), ประกาศ (71), แผนซ้อม (72), โน้ตโค้ช (73), นาทีลงเล่น (74), ผู้ช่วยโค้ช (75), รายชื่อ (76), กระดานวางแผน (28, 68)
  - ผลคือ **ถ้ายังไม่สมัครรายการ ก็ยังใช้เครื่องมือเหล่านี้ไม่ได้เลย**
- พอรายการแข่งจบ ทีมก็จบไปกับรายการนั้น ฤดูกาลถัดไปต้องสร้างทีมใหม่และเชิญนักกีฬาใหม่ทั้งหมด ข้อมูลเก่าอย่างนัดซ้อม แผนซ้อม และโน้ตไม่ตามมาด้วย

## 2. แบบที่เสนอ: "ทีมของฉัน" (ถาวร) + "ทีมที่ลงแข่ง" (ต่อรายการ)

```
ทีมของฉัน  (teams.tournament_id = NULL, kind = 'club')
  ├─ สมาชิก (team_members): เชิญด้วยอีเมล นักกีฬากดตอบรับเอง (เหมือนเดิม)
  ├─ นัดซ้อม · ประกาศ · แผนซ้อม · โน้ตโค้ช · ผู้ช่วยโค้ช · กระดานวางแผน (ใช้ของเดิมทั้งหมด)
  └─ พาทีมลงแข่ง ──► ทีมที่ลงแข่ง  (teams.tournament_id = รายการ, source_team_id = ทีมของฉัน)
                        ├─ รายชื่อ: เลือกจากสมาชิกของทีมของฉัน
                        └─ ส่งสมัคร · สลิป · ผู้จัดตรวจ · ผลแข่ง (flow เดิมของ sql/20 ไม่เปลี่ยน)
```

**ทำไมเลือกแบบนี้**
- เครื่องมือทุกตัวผูกกับ `teams.id` อยู่แล้ว ทีมของฉันจึงเป็นแถวใน `teams` เหมือนเดิม แค่ไม่มีรายการแข่ง เครื่องมือเดิมใช้ได้ทันที
- flow สมัคร สลิป ตรวจทีม ผลแข่ง และตารางแข่ง (sql/20, 55, 56) ไม่ต้องรื้อ เพราะทีมที่ลงแข่งก็ยังเป็นแถว `teams` แบบเดิม
- ทีมของฉันอยู่ข้ามฤดูกาล สมาชิก นัด แผน และโน้ตไม่หาย

**แบบที่ไม่เลือก**
- **ตาราง `squads` ใหม่ แล้วย้ายเครื่องมือทั้งหมดไปผูกกับ squad:** ต้องแก้ SQL69–76 ทุกไฟล์ เสี่ยงมาก
- **ตาราง `team_registrations` แทน `teams.tournament_id`:** ต้องแก้ flow สมัคร ผลแข่ง และตารางแข่งทั้งหมด
- **ใช้ `organization_teams` (sql/26):** มีอยู่แล้ว แต่เป็นทีมใต้องค์กร ไม่มีสมาชิก และไม่มีเครื่องมือ ต้องสร้างใหม่หมด

## 3. สิ่งที่ต้องเปลี่ยน

### SQL78 (ไฟล์ใหม่ทั้งหมด ไม่แก้ไฟล์ที่ลงแล้ว)
| # | เปลี่ยน | เหตุผล |
|---|---|---|
| 1 | `teams.tournament_id` ให้เป็นค่าว่างได้ (precheck ดูก่อนว่าบน Production ตอนนี้บังคับ NOT NULL หรือไม่) | ทีมของฉันไม่มีรายการแข่ง |
| 2 | เพิ่ม `teams.kind` ('club' / 'entry') และ `teams.source_team_id` | แยกทีมของฉันกับทีมที่ลงแข่ง และรู้ว่าทีมที่ลงแข่งมาจากทีมไหน |
| 3 | `create_my_team(p_name, p_age_group)`: ทีมของฉันเริ่มที่สถานะ `draft` จึงเชิญคนได้ตลอด จำกัดคนละ 20 ทีม และสร้างได้ทุกคนที่สมัครเป็นโค้ช (persona `coach_organizer`) | สร้างทีมได้ทันที |
| 4 | `enter_tournament_from_team(p_team_id, p_tournament_id, p_athlete_ids[])`: สร้างทีมที่ลงแข่งจากทีมของฉัน ถ้ากดซ้ำได้ผลเดิม (กันสองแถวด้วย unique index `(tournament_id, created_by)` ของเดิม) | พาทีมลงแข่ง |
| 5 | redefine ฟังก์ชันที่ใช้ `join public.tournaments` แบบ inner (เช่น sql/68 กระดานวางแผน) เป็น left join | ทีมที่ไม่มีรายการจะได้ไม่หายจากผลลัพธ์ |
| 6 | สิทธิ์อ่าน `teams` และ `team_members` เดิมเป็น "ผู้สร้าง / ผู้จัดของรายการ / แอดมิน" ใช้ได้กับทีมของฉันโดยไม่ต้องแก้ เพราะผู้สร้างอ่านได้อยู่แล้ว | ตรวจด้วยเทสในเครื่องจำลอง |
| 7 | `invite_team_member` (sql/20) ใช้กับทีมของฉันได้อยู่แล้ว: ตรวจ `created_by` และสถานะ `draft` และการกันซ้ำต่อรายการไม่ทำงานเมื่อรายการเป็นค่าว่าง | ไม่ต้องแก้ แต่ต้องมีเทสยืนยัน |

### แอป
- **หน้า "ของฉัน" ของโค้ช:** การ์ดหลัก "สร้างทีมของฉัน" (ชื่อทีม + รุ่นอายุ) แล้วไปหน้าทีมได้ทันที ดู v10-2
- **หน้าทีม `/team-members/[id]`:** ใช้ได้กับทีมของฉันเลย เพิ่มปุ่ม "พาทีมลงแข่ง" ที่ให้เลือกรายการ และเลือกนักกีฬาจากสมาชิก
- **`/team-members`:** หมวด "ทีมที่ฉันดูแล" แยกเป็นทีมของฉัน (ถาวร) และทีมที่ลงแข่ง (ต่อรายการ)
- **สมัครจากหน้ารายการแข่ง:** แบบเดิม (ตั้งชื่อทีมใหม่) ยังใช้ได้ และเพิ่มตัวเลือก "ใช้ทีมของฉัน"

## 4. เรื่องที่เจ้าของตัดสินแล้ว (ตามที่แนะนำทั้ง 4 ข้อ)

| # | คำถาม | ผมแนะนำ |
|---|---|---|
| D1 | ตอนพาทีมลงแข่ง สมาชิกที่ตอบรับทีมของฉันแล้ว **ต้องตอบรับซ้ำ** สำหรับรายการแข่งไหม (รายชื่อทีมที่ลงแข่งผู้จัดเห็น และผลแข่งเป็นสาธารณะ) | **ไม่ต้องตอบรับซ้ำ แต่แจ้งเตือนนักกีฬาและผู้ปกครอง** และถอนตัวได้ก่อนโค้ชกดส่งสมัคร โดยคำเชิญเข้าทีมของฉันต้องเขียนชัดว่า "โค้ชอาจพาคุณลงแข่งในรายการต่าง ๆ" ส่วนคนที่ตอบรับไว้ก่อนมีข้อความนี้ ให้ขึ้นเป็น "รอตอบรับ" |
| D2 | ทีมที่สร้างผ่านรายการแข่งแบบเดิม (เช่น liverpool) ควรแปลงเป็นทีมของฉันไหม | **ไม่แปลงอัตโนมัติ** มีปุ่ม "เก็บเป็นทีมของฉัน" ให้กด ซึ่งจะสร้างทีมของฉันจากรายชื่อนั้น |
| D3 | ใครสร้างทีมของฉันได้ | ทุกคนที่เลือก "โค้ช" ตอนสมัคร (persona `coach_organizer`) เหมือนการสมัครทีมเดิม คนละไม่เกิน 20 ทีม |
| D4 | นักกีฬาหนึ่งคนอยู่ได้หลายทีมของฉันไหม (เช่น ทีมโรงเรียน + ทีมสโมสร) | **ได้** เพราะชีวิตจริงเป็นแบบนั้น แต่ทีมที่ลงแข่งยังคงกฎเดิม คือในรายการเดียวกันอยู่ได้ทีมเดียว |

## 5. เช็กลิสต์ใช้ทั้งประเทศ (`AGENTS.md`)
1. **ข้อมูล 100 เท่า:** มีดัชนี `(created_by, kind)` สำหรับ "ทีมของฉัน" และรายชื่อในหน้าทีมแบ่งหน้าตามเดิม
2. **คนกดพร้อมกัน:** `enter_tournament_from_team` กดซ้ำได้ผลเดิม และ unique index เดิมกันการสมัครซ้ำในรายการเดียวกัน
3. **ข้อมูลเด็ก:** สิทธิ์อ่านเดิมไม่กว้างขึ้น ทีมของฉันเห็นได้แค่ผู้สร้าง ผู้ช่วยโค้ช และสมาชิก ตามเดิม และ D1 ต้องตัดสินก่อน
4. **งานมือที่โตตามจำนวนผู้ใช้:** ไม่มี เพราะโค้ชสร้างทีมเอง ไม่ต้องรอแอดมิน
5. **หลักฐาน:** ต้องทดสอบ SQL78 ในเครื่องจำลองก่อน แบบเดียวกับ SQL70–77 (precheck, apply ซ้ำ, rollback, เทสสิทธิ์ทุกบทบาท, กดพร้อมกัน 20 ครั้ง)

## 6. ลำดับงานหลังตกลงแบบ
1. SQL78 + precheck/postcheck/down + เทสในเครื่องจำลอง → ลง Staging → ลง Production (อนุมัติแยก)
2. แอป: สร้างทีมของฉัน + หน้าทีม + การ์ดในหน้า "ของฉัน" (เขียนเทสก่อนโค้ด)
3. แอป: พาทีมลงแข่ง + เลือกนักกีฬา + แจ้งเตือนตาม D1
4. เทสด้วย Claude in Chrome บนเว็บจริงก่อนเปิดให้ผู้ทดสอบ W1
